# AI 聚合平台「三合一」融合方案

> 目标：把 **ai-bot.cn（流量导航）** + **AI Agent Store（能力市场）** + **AI 超市（交易货架）** 三种模式融合为一个网站，减少模式差异、扩大客群、增加信任、补全短板，并用「流量型」业务逻辑驱动多类型商业闭环。

---

## 零、一句话结论

用 **「一个目录 · 三种门面 · 一套会员」** 的统一骨架，把三种模式从「三个网站」变成「一个网站的三个视图」：

- **流量型导航**做获客引擎（把人引进来）
- **Agent 能力**做价值深度（把人留深）
- **超市交易**做变现出口（把钱收上来）
- **一套会员**打通三种付费，让用户感知「一个平台」而非「三个网站」

---

## 一、三种模式定位拆解

| 维度 | ai-bot.cn（导航） | AI Agent Store（市场） | AI 超市（本项目现状） |
|---|---|---|---|
| 本质 | 流量型目录 | 能力型商城 | 交易型货架 |
| 核心资产 | SEO 流量 + 榜单公信力 | Agent 可调用 + 开发者生态 | 购物车 + 结账心智 |
| 变现方式 | 广告 / 收录费 / 联盟 CPS | 订阅抽佣 / 用量计费 | 商品交易 / 套餐 / 会员 |
| 客户群体 | 泛流量（C 端找工具） | 开发者 / 企业（B 端） | 普通 C 端 |
| 短板 | 有流量、无交易 | 有能力、无流量 | 有交易、缺流量与深度 |

**关键洞察**：三种模式其实是「同一条用户旅程的三个阶段」，不是三个割裂的业务——发现（导航）→ 体验（Agent）→ 购买（超市）。融合的本质是把这条旅程装进一个网站。

---

## 二、融合三原则（减少差异化的本质）

1. **One Catalog，三种 Facade（一个目录，三个门面）**
   不做三套独立网站，而是一个统一的「条目（Item）数据模型」承载三种形态；三种模式只是同一份数据的三种渲染视图，用 Tab 切换而非跳站。

2. **一个搜索框、一套分类、一条旅程**
   用户不需要理解「这是导航还是超市还是 Agent 市场」，他只需「搜一个东西」或「逛一个品类」，系统自动呈现最合适的门面。

3. **流量做入口、交易做出口、能力做深度**
   流量型导航负责把人引进来；Agent 能力负责把人留深；超市交易负责把钱收上来。

## 三、统一骨架设计（模块顺序）

### 3.1 统一条目数据模型（Item Schema）

```
Item（条目）
├── 基础：id / 名称 / 图标 / 一句话描述 / 标签 / 分类 / 评分
├── 导航属性：官网 URL / 榜单排名 / 月访问量 / 收录时间   ← ai-bot 门面
├── 能力属性：Agent 调用入口 / API / 订阅价格 / 免费额度   ← Agent 门面
└── 交易属性：SKU / 价格 / 套餐 / 库存状态 / 评价 / 加购   ← 超市门面
```

一套数据、三组属性，按门面渲染时只暴露对应属性。

### 3.2 页面骨架（自上而下模块顺序）

1. **顶部导航**：Logo + 全局搜索 + 分类入口 + 会员入口（统一，弱化模式切换）
2. **Hero（轻）**：一句价值主张 + 全局搜索框 + 热门分类 chips（流量型 Hero 不宜重）
3. **分类导航**：品类卡 / 横向 chips（承接 SEO 分类词）
4. **榜单 / 热门**：本周热门 / 新收录 / 编辑精选（信任 + 流量钩子）
5. **主列表（三视图可切换）**：
   - 发现视图（导航门面）= 卡片列表 + 排序 + 筛选
   - 能力视图（Agent 门面）= 可试用 + 订阅按钮
   - 货架视图（超市门面）= 货架 + 加购（复用现有 ShelfCard）
6. **信任背书区**：收录数 / 评分 / 官方入驻标识 / 案例 logo 墙 / 媒体
7. **场景解决方案**：按客群分层（个人 / 开发者 / 企业 / 创作者）
8. **底部**：关于 / 友链 / 备案 / 分类聚合页（SEO 友好）

### 3.3 对应项目现状的改造点

- 现有 `/products` 货架页 → 升级为「主列表三视图」容器
- 现有 `ProductCard / ShelfCard / ShelfGlowCard` → 抽象为统一 `ItemCard`（三视图共用）
- 新增 `/tools/[slug]` 工具落地页（SEO 长尾 + Agent 调用 + 加购三合一）
- 新增 `/rank` 榜单页、`/collections` 精选页
- `src/data/products.ts` 中 **11 个缺 description 的条目 → 补全**（SEO 与卡片展示必需）

## 四、业务逻辑：流量引擎 + 四层商业闭环

### 4.1 流量引擎（获客层）

- **SEO 长尾矩阵**：每个条目一个落地页（「XX 是什么 / 怎么用 / 替代品 / 评测」）
- **内容矩阵**：榜单、对比、教程、场景清单、周报
- **反链策略**：免费工具 / 榜单页自然获取外链
- **双语**：中英双语，覆盖国内 + 出海流量

### 4.2 四层商业闭环（变现层，从浅到深）

| 闭环 | 类型 | 机制 |
|---|---|---|
| ① 联盟导流闭环 | 流量型 | 「去官网」跳转带联盟链接，按注册/付费 CPS 分佣 |
| ② 广告 / 收录闭环 | 流量型 | 榜单位、置顶位、广告位、收录费 |
| ③ Agent 订阅闭环 | 能力型 | 平台托管 Agent → 用户订阅 → 平台抽佣 30% + 用量计费 |
| ④ 超市交易闭环 | 交易型 | 套餐组合、打包购买、会员（复用现有购物车/结账） |

### 4.3 会员贯通（减少差异化的变现关键）

一个会员权益横跨三种模式，让三种模式共享一个付费体系：

- **导航**：去广告、优先展示
- **Agent**：每月调用额度、订阅折扣
- **超市**：会员价、打包套餐折扣

---

## 五、增加客户群体（从泛流量到 B 端）

- 泛流量用户（导航 → 发现工具）
- 普通 C 端（超市 → 交易）
- 开发者（Agent → 调用 / 订阅）
- 企业（B 端采购、团队版、私有化）
- 创作者 / 小团队（套餐、组合）
- 出海用户（双语）

---

## 六、减少分层记忆（认知减负）

- 一个网站、一个搜索框、一套分类
- 视图切换用 Tab（发现 / 能力 / 货架），不跳独立站点
- 分类层级 ≤ 2 层（大类 → 子类），不做多层菜单
- 统一卡片结构：无论哪个视图，卡片字段一致（图标 + 名称 + 描述 + 标签 + 动作按钮）

---

## 七、增加信任背书

- 真实数据：收录数、月访问量、真实评分
- 编辑精选 / 评测：人工背书
- 官方入驻认证：`✓ 官方` 标识
- 案例 / logo 墙 + 媒体报道
- 排序规则公开（透明化，反刷榜）

---

## 八、补全差异化短板

| 模式 | 短板 | 补全动作 |
|---|---|---|
| ai-bot | 有流量、无交易 | 加「交易闭环 + 会员」 |
| Agent Store | 有能力、无流量 | 加「SEO 内容矩阵 + 榜单」 |
| 超市 | 有交易、缺流量与深度 | 加「流量引擎 + Agent 能力」 |

---

## 九、实施计划（分阶段落地）

| 阶段 | 内容 | 周期 |
|---|---|---|
| **P0 统一数据层** | 扩展 Item Schema；补全 11 个缺 description 条目；抽象统一 ItemCard（复用 ShelfCard 视觉） | 1–2 周 |
| **P1 流量型改造** | 新增 `/tools/[slug]` 落地页；`/rank` 榜单页、`/collections` 精选页；SEO（sitemap、meta、结构化数据、内链） | 2–4 周 |
| **P2 能力接入** | Agent 调用层（试用 + API 代理 + 订阅计费）；官方入驻认证体系 | 4–6 周 |
| **P3 会员贯通 + 信任** | 统一会员权益（导航/Agent/超市三合一）；信任背书模块（数据、案例、媒体） | 6–8 周 |
| **P4 变现接入** | 联盟 CPS 接入、广告位、抽佣结算 | 8–10 周 |

## 十、成功指标（KPI）

- **流量**：收录条目数、自然流量月增长、落地页收录率
- **转化**：注册率、加购率、订阅转化率、会员续费率
- **收入**：联盟 CPS、广告、Agent 抽佣、会员 ARPU

## 十一、整改实施基线（2026-08-30）

本节是方案落到当前代码时的约束基线。后续改造不得跳出前述「一个目录 · 三种门面 · 一套会员」方向，也不得把规划中的能力伪装成已经上线。

### 11.1 当前已落地

- `/products` 作为统一主列表，使用同一个搜索、同一套场景分类和三种视图：
  - **发现**：名称、简介、标签、场景与详情入口；
  - **能力**：只展示当前真实标记为 `live` 的工作台能力；
  - **货架**：复用现有价格、加购和开通流程。
- `src/lib/unified-catalog.ts` 作为 One Catalog 适配层，统一整理发现、能力和交易字段。
- `src/components/ItemCard.tsx` 作为三门面的统一卡片入口；货架视图继续复用已验证的 `ShelfCard`。
- `/tools/[slug]` 作为 SEO 条目落地页，内容、价格和交付状态仍来自统一目录。
- `/rank` 为编辑精选，明确披露按目录运营顺序排列，不冒充销量榜、访问榜或评分榜。
- `/collections` 按既有场景组织条目，不另建一份产品数据。
- 首页改为轻量 Hero：全局目录搜索 + 热门场景入口 + 支持模型，不再让用户先理解三种商业模式。
- sitemap 纳入 `/tools/[slug]`、`/rank`、`/collections`，产品 SEO 主地址统一到 `/tools/[slug]`。

### 11.2 真实业务口径

- 在售数量来自公开目录返回值，不手写固定数字。
- 在线能力只由现有 `resolveDelivery(product) === "live"` 判定。
- 价格、SKU、加购、结账、订阅与工作台继续复用现有真实流程。
- `setup` 与 `playbook` 不进入「在线能力」门面，不得写成可直接调用。
- 目录已有 86 个公开条目，当前公开数据中缺失 `description` 的条目为 0；原方案中“补 11 个描述”已完成，不再重复造条目。

### 11.3 暂不展示（等待真实数据或后端闭环）

以下字段虽然保留在方案中，但没有核验数据前不展示、不造数：

- 官网联盟链接、CPS 归因与佣金；
- 月访问量、真实用户评分、销量和趋势；
- `✓ 官方` 入驻认证；
- 免费额度、公开 API、开发者分成；
- 广告位、付费置顶、收录费；
- 统一会员价格、权益、团队版和私有化承诺。

### 11.4 视觉语言

- **基底**：深黑背景，减少模式切换造成的视觉割裂；
- **容器**：低透明毛玻璃与细描边，表达“同一平台中的不同视图”，不做三个独立站点；
- **场景色**：沿用 `SCENE_TONE`，颜色用于识别需求场景，不用于伪造状态；
- **状态色**：绿色仅表示真实在线，蓝色表示待配置，琥珀色表示方案陪跑；
- **层级**：轻 Hero → 搜索/分类 → 三视图 → 主列表 → 客群入口，严格对应 3.2 页面骨架；
- **动效**：只使用短距离位移、边框和透明度反馈；不让重动画压过搜索、比较和开通动作。

### 11.5 用户旅程

```text
搜索 / 场景入口
  → 发现视图（了解与比较）
  → 能力视图（核对是否真实在线）
  → 货架视图（价格、加购、开通）
  → 工作台（按任务匹配模型完成需求）
```

个人、开发者、企业与创作者共享这条旅程，只改变默认筛选和内容组织，不拆分独立网站。
