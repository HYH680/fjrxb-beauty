# 分类方式分析与改进方案

> 日期：2026-08-30

## 一、分类方式分析：精选 vs 行业细分

### 1.1 两种方式的本质区别

| 维度 | 精选分类 | 行业细分 |
|------|----------|----------|
| **逻辑** | "什么是最好的" | "我需要什么" |
| **适合** | 内容少、需要推荐 | 内容多、需要导航 |
| **用户心态** | 被动接受推荐 | 主动寻找目标 |
| **维护成本** | 需要持续人工运营 | 一次性分类即可 |

### 1.2 竞品采用方式

| 竞品 | 分类方式 | 特点 |
|------|----------|------|
| **AI-Bot.cn** | 行业细分 | 左侧分类导航，9大类 |
| **Futurepedia** | 行业细分 | 顶部分类标签，10大类 |
| **Product Hunt** | 精选为主 | 每日精选 + 分类 |

### 1.3 我们的三视图应该如何分类

| 视图 | 推荐分类方式 | 理由 |
|------|-------------|------|
| **发现视图** | 精选 + 场景 | "发现"=探索未知，需要推荐引导 |
| **能力视图** | 行业细分 | "能力"=按需求找，按场景/行业更直观 |
| **货架视图** | 行业细分 | "采购"=按需求筛选，行业细分更高效 |

### 1.4 结论

**推荐方案**：采用「精选 + 行业细分」混合模式

- **发现视图**：「编辑精选」+「热门趋势」双轨
- **能力/货架视图**：按行业细分（现有分类已足够）

## 二、留白与科技感分析

### 2.1 用户观点

用户认为：科技感网站不需要留白，不留白更凸显科技力。

### 2.2 分析

| 方案 | 适合场景 | AI行业常见做法 |
|------|----------|---------------|
| **留白** | 消费级产品、内容驱动 | Notion、Linear |
| **紧凑** | 工具类、效率导向 | Vercel、Railway |

### 2.3 结论

**采纳用户观点**：采用紧凑布局，强调科技力量感。

## 三、图标方案：去AI味 + 科技感

### 3.1 当前问题

当前使用 🔭🔍🔮 等图标，这些是常见AI图标，缺乏科技感。

### 3.2 科技感图标选择

| 场景 | 推荐图标风格 | 具体图标 |
|------|-------------|----------|
| **发现** | 探索/雷达 | `Radar` `Scan` `Crosshair` `Globe` |
| **能力** | 芯片/模块 | `Cpu` `Grid3x3` `Box` `Layers` |
| **货架** | 货架/商店 | `Store` `Package` `Warehouse` |

### 3.3 具体替换方案

| 当前图标 | 替换为 | 风格 |
|---------|--------|------|
| 🔭 Compass | `Radar` | 科技探测感 |
| 🤖 Bot | `Cpu` | 芯片感 |
| 🛒 ShoppingBag | `Warehouse` | 仓储感 |
